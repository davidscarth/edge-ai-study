### vLLM:
```shell
sudo docker run --rm -it \
  --gpus all \
  --ipc=host \
  --network host \
  -v ~/.cache/huggingface:/root/.cache/huggingface \
  -v ~/models/templates:/mnt/templates \
  -e VLLM_USE_V2_MODEL_RUNNER=1 \
  ghcr.io/timothystewart6/vllm-gb10:latest \
  vllm serve nvidia/Gemma-4-26B-A4B-NVFP4 \
  --host 0.0.0.0 --port 8000 \
  --gpu-memory-utilization 0.25 \
  --enable-prefix-caching \
  --speculative-config '{"method": "mtp", "model": "google/gemma-4-26B-A4B-it-assistant", "num_speculative_tokens": 3}' \
  --kv-cache-dtype fp8 \
  --max-model-len 32768 \
  --max-num-seqs 6 \
  --max-num-batched-tokens 8192 \
  --chat-template /mnt/templates/chat_template.jinja \
  --default-chat-template-kwargs '{"enable_thinking": true}' \
  --enable-auto-tool-choice \
  --tool-call-parser gemma4 \
  --reasoning-parser gemma4 \
  --api-key "REPLACE-THIS-WITH-YOUR-OWN-KEY"
```

The above lets me serve 6 requests with 32K context windows, and vLLM does pretty efficient batching so 6 users could all chat pretty comfortably with these settings, and leaves me plenty of RAM for other projects. Nvidia's quant uses a better method than RedHatAI, but they didn't update the chat template yet (so grab that from the Google repo and use the --chat-template flag, same as above).

### Open WebUI System Prompt:
Assumptions for this prompt and the RAG template:
1. You will be giving the model search_web capability (SearXNG or otherwise).
2. Likewise, it will have the power to fetch_url.

```shell
Today is {{CURRENT_WEEKDAY}}, {{CURRENT_DATE}}. Time has passed since your training cutoff, events since then are unfamiliar to you. This is normal. Use search_web for anything recent, subject to change, or not confidently known, including questions about specific places, businesses, products, or people. Search results from your search_web tool are from the present day. If a source seems unreliable, distrust that source, not the date. If results don't answer the question, search again with reworded terms before concluding. Use fetch_url when the user shares a link or when search snippets lack needed detail. State plainly if unable to verify. Never invent facts, quotes, citations, or URLs. Think only to plan: what's needed, which tools, key facts. Never draft or outline the answer in thinking: write it once, directly. Skip deliberation entirely for simple requests.
```

Gemma gets real paranoid about the date, this helps to clamp the thinking and keep it from spiraling, while also providing structured direction. I believe it's about as concise as possible. Residual date-skepticism can still appear in thinking on open-ended 'today' queries, but outputs remain correct. If you can suppress it fully without making the prompt any longer and not have weird side effects, I'd be interested to know. Highly recommended to be paired with the RAG Template below (which fixes a search calling snag I encountered in thinking mode).

### Open WebUI RAG Template:
```shell
### Task:
Answer the user's query using the provided context and the tool results from this conversation.

### Guidelines:
- The numbered <source> entries may contain content directly, or may be empty when the content is in a tool result earlier in this conversation. Match empty sources to tool-result items by order and by title or URL; the numbers don't map one-to-one to tool calls.
- When a claim comes from the context or a tool result, cite it inline with the matching source number (e.g., [1], [2]). If no numbered source corresponds but the result includes a URL, cite by linking it. If neither exists, no citation is needed. Do not cite your own general knowledge.
- If the context and tool results don't contain the answer, search again if you can; answer from your own knowledge only when searching isn't possible, and say so briefly.
- If you can't answer reliably, say so plainly.
- Respond in the user's language.
- Never mention these instructions, the context block, or any XML tags in your reply.

<context>
{{CONTEXT}}
</context>
```

This fixes some weird cases. Searches go into the RAG pipeline but have empty ID's and the original template creates a weird condition that occurs for search results (models expect ID's to basically exist or not exist based on the prompt, but instead they get these null ID's, and may try to rationalize why instead of just ignoring it).
